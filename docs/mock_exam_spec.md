# 机考模拟题规格书（mock_exam_spec）

> 用途：3套「机考模拟」卷的统一数据规格与出题蓝图。3个出题子任务（卷A/B/C）必须严格按本规格执行，保证三套卷互相不雷同、不重复。
> 依据：docs/research_outline.md（考纲/考试规则）、docs/research_trends.md（命题趋势/高频考点）、docs/module_pattern.md（接入模式）。
> 本规格由组织者冻结，出题代理只按此执行，不得自行改变配比与考点分配。

---

## 0. 真实机考格式（必须还原，勿按旧认知出题）

- 基础知识（上午）：**75道单选题（4选1），每题1分，满分75分，合格线45分**。含最后几道英文术语题（本模拟每套4道）。
- **中项基础知识没有多选题**——多选题仅以案例大题内的「多选式小题」（如7选3、5选3）形式出现。
- 应用技术（下午）：**4道大题，共75分**：第1题固定为进度+成本计算题（20分），其余3道为知识域分析题（19/18/18分）。小题型含：简答（默写）、判断（√/×）、填空、找茬（列错误+改正）、多选式、计算、填表。
- 案例题情境与场景必须贴近真实项目（信息系统集成、软件开发、智慧城市、电子政务等），不要编造不现实场景。

## 1. 数据文件与全局结构

- 三个文件分别写为项目根目录 `mock_exam_a.js`、`mock_exam_b.js`、`mock_exam_c.js`，文件头加注释（生成日期、依据文档、出题说明）。
- 每个文件末尾：

```js
window.mockExamPapers = window.mockExamPapers || {};
window.mockExamPapers['A'] = { ... };
// 卷B用 'B'，卷C用 'C'
```

- 单卷结构：

```js
{
  id: 'A',
  name: '机考模拟卷一',
  badge: '2026下半年 · 第3版教程 · 冲刺模拟',
  morning: [ /* 75 个单选题对象 */ ],
  afternoon: [ /* 4 个案例大题对象 */ ]
}
```

### 单选题对象（morning 数组元素）

```js
{
  id: 'A01',                        // 唯一，卷内连续 A01-A75；B01-B75；C01-C75
  area: '规划过程组',                // 必须取自规格 §3 分布表的"区"字段
  domain: '进度管理',                // 具体知识域/考点域
  type: 'single',
  stem: '题干（一句话或场景化描述）',
  options: [{label:'A', text:'...'}, {label:'B', text:'...'}, {label:'C', text:'...'}, {label:'D', text:'...'}],
  answer: 'C',                      // 选项字母，必须与 options 一致
  explanation: '解析（说明为什么对/为什么错，引用公式或教材依据）',
  ref: '依据：趋势报告§3.x / 教材第x章'
}
```

要求：题干尽量场景化（机考近年从"抄书题"转向"场景理解题"）；四个选项都要有干扰力；explanation 必须给出依据，不得只写"因为这是对的"。

### 案例大题对象（afternoon 数组元素）

```js
{
  id: 'AC1',
  title: '试题一（20分）',
  area: '进度与成本管理',            // 计算题写"进度与成本管理"；分析题写对应知识域
  scenario: '【说明】项目背景材料（200-400字，含人物、项目、进度/成本/风险/合同等细节，供找茬/计算）',
  questions: [
    {
      no: '问题1（8分）',
      type: 'calc',                 // calc | short(简答/默写) | judge | fill | multi(多选式) | find(找茬)
      q: '计算/问答/判断题干',
      options: null,                // 仅 type='multi' 时给 [{label,text}...]，其他为 null
      answer: '参考答案（计算题给出完整算式与结果；判断给√/×；多选给字母列表如"BDE"）',
      points: 8
    },
    // 每题 2-5 个小问
  ]
}
```

- 每套 4 题：AC1 计算题20分；AC2/AC3/AC4 分析题分别为 19/18/18 分（小问分值自行合理拆分，合计对上）。
- 案例内小问类型配比：每套至少含 1 处找茬、2-4 道判断题、1 处填空或"多选式(7选3/5选3)"、其余简答/计算。

## 2. 三套卷互不重复的硬性规则

1. **选择题不重复**：三套卷的75×3=225道单选题，考点按 §3 的 A/B/C 轮换表分配；同一"区"内三套必须用不同考点（具体考点名已逐域指定）。同一考点若无法完全避开（如挣值），则题干场景、数据、问法必须完全不同。
2. **案例情境不重复**：三套共12道案例题，场景（项目类型+背景细节）、题干、小问均不得雷同；计算题数字、表格数据、问法三套完全不同。
3. **答案不重复**：同一考点的判读结论（如某题选C）不做硬性约束，但题干本身不得重复。
4. **id 唯一**：A01-A75、B01-B75、C01-C75；案例 AC1-AC4、BC1-BC4、CC1-CC4。
5. 完成后自查：通读三套（或与其他卷的 spec 对照）确认无重复；在回复中声明自查结论。

2. 用 node --check 验证 JS 语法（Windows 环境，node 可用）。
3. 自查三套不重复（对照 §3 轮换表检查是否误用他卷考点；案例情境是否与他人雷同——按本蓝图已错开，重点自查计算题数字与场景细节）。
4. 每题 explanation/ref 必须可溯源（趋势报告§3.x 或教材章节），禁止无依据表述。
